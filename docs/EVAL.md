# 评测体系

回答一个问题：**改完代码，这套东西是变好了还是变坏了？**

没有固定输入，"质量"就只能靠感觉说。所以这里有一组固定的调研需求（黄金集）、
一组从报告正文里直接读出来的指标、一条写死的阈值线，和一个会真的红/绿的退出码。

```
python -m eval.run_eval --gate                    # 零成本，进 CI
python -m eval.run_eval --replay                  # 真实录制，零成本
python -m eval.run_eval --live --repeat 3 --judge # 花钱，写文档前跑一次
python -m eval.run_eval --from-db                 # 库里的报告，不重跑
```

---

## 先看这张表，以及它最下面那行

| 方式 | 跑什么 | 回答的问题 | 花钱 |
|---|---|---|---|
| `--gate` | 黄金集 × **mock** provider | 代码改完，流水线的**结构性行为**有没有退步 | 0 |
| `--replay` | 有录制物的 query × cassette 回放 | **真实适配器那条路径**离线还能不能走通 | 0 |
| `--live` | 黄金集 × 真实 provider | 这套东西现在的**质量**到底是多少 | 有 |
| `--from-db` | 库里已有的报告 | 昨天那批报告长什么样（不重跑） | 0 |

> **mock 闸门是回归网，不是质量尺。**
>
> mock 的三个 provider **都不看 query**——实测跑 `notion-vs-obsidian` /
> `su7-vs-zeekr007` / `vague-coffee-market` 三条，指标逐项相同
> （216 条证据、33 个信源、4 个维度、覆盖率 1.00）。
> 所以"跑了 22 条"在 mock 下**不等于"覆盖了 22 种输入形态"**，
> 它就是同一种输入跑了 22 遍。
>
> 它的绿色只说明"没坏"，不说明"好"。质量那句话只能由 `--replay` 和
> `--live` 说。

这一条写在最前面，是因为**闸门很容易被当成它做不到的东西**：
一个 22 条全绿的结果读起来像"系统很健康"，
而它实际上只证明了"证据流、事件序、返工循环还在"。

## 黄金集

[`eval/golden.yaml`](../eval/golden.yaml)，**22 条**（21 条 `queries` +
1 条 `ambiguity`），固定，入库。

### 按证据形态选，不按品牌知名度选

每条 query 的 `note` 不是"这条问的是什么"，而是**它在测什么**。
一条不测任何东西的 query 只会稀释指标：跑绿了不能说明任何事，
跑红了也不知道该去看哪一块。

覆盖的是**证据形态的差异**：

| 形态 | 代表条目 | 测什么 |
|---|---|---|
| 规格公开、横评多 | `dji-mini4-vs-autel-evo` | 规格类证据的**可信度评分** |
| 港股财报可比 | `youzan-vs-weimob` | 财报证据能否进入财务维度 |
| 主要靠 UGC 口碑 | `dewu-vs-shihuo` | 舆情标注的**混合比例披露** |
| 几乎没有公开信息 | `vague-coffee-market` | 澄清阶段会不会问出对比对象 |
| 维度高度重合 | `notion-vs-obsidian` | 功能矩阵会不会给出一片 4 分 |
| 格局已经翻转 | `figma-vs-sketch` | 判断会不会**依赖过期证据** |
| 报道量极大 | `taobao-vs-pinduoduo` | 去重与独立信源上限 |
| 路线之争而非参数之争 | `nio-vs-li` | deep 档的深度回报 |

三档模式都至少被回放过一次（`nio-vs-li` / `byd-han-vs-model3` 是 deep，
`chatgpt-vs-claude` 是唯一的 expert）——**三档里如果有一档从来没被回放过，
它坏了是不会有人知道的。**

### 已知代价

- **录制物是 JSONL，含抓回的网页正文，体量在几 MB 量级**，
  且随 query 增加线性增长。这是"CI 能离线跑完整条流水线"付的价。
- **key 由请求内容决定**（`{kind, messages, tier, temperature, max_tokens, json_mode}`），
  所以**改一个字（prompt、query、temperature）就会全部 miss**。
  这是刻意的：回放的价值是证明"这条确定的路径能跑通"，不是假装一切照旧。
  代价是——录制过期时 `--replay` 会红，而且报 "没录制，跳过" ×N。
  **这是有意让它红的**：让闸门绿着跳过，等于把"这套东西现在没有被测"
  说成"这套东西测得挺好"。

## 指标从哪来：一个都不重算

[`eval/metrics.py`](../eval/metrics.py) 的规矩是硬的：
**能读的就读，读不到就报缺，绝不退化成"自己算一个差不多的"。**

`backend/app/core/analysis/metrics.py` 的 `compute_metrics(ctx)` 已经算过一遍，
结果跟着报告落库在 `body["metrics"]`。评测层若再算一遍，就会有
**两份"维度覆盖率"的定义**，然后它们在某个边界上分叉。

这个坑在 xm3 里已经踩过两次——`问题记录.md` 问题 37：
`buildGraph` 与 `pickEvidences` 各自实现了一遍"哪条证据进图"。

### 读不到就报缺，不当成 0

报告里压根没有 `metrics` 时抛 `MissingMetrics`，而不是返回一个空字典。
单独一个异常类型，是因为**它和"某个键是 0"必须能被区分开**：

- 见到 `MissingMetrics` → 这是一份不该进评测的报告（回放产物、或评测层加字段之前落的库）
- 见到 `0` → 这次真的跑出来是 0

**把"没测到"当成"测出来是 0"，是这个项目反复在防的那类错**
（专家名册的 `stats` 就是这个形状：那些 0 是"还没被量过"）。

同一个道理贯穿到聚合：`_pooled()` 在分母合计为 0 时返回 `None` 而不是 0，
因为 `None` 会让闸门说"无法判定"，而 0 会让它说"通过了"。

### 数值键是白名单

`NUMERIC_KEYS` 是一个写死的元组（30 个键），不是"把 `metrics` 里所有数都拿来"。
理由：非标量的键（`platforms` / `byPurpose` / `byModel`）聚起来没有意义，
而"自动发现数值键"会让新增一个键**静默进入闸门**——
一个没人写过阈值的指标出现在表里，读起来像是被检查过的。

`bool` 被显式挡掉：它是 `int` 的子类，不挡的话 `qualityGatePassed`
会被当成 1.0 参与聚合。

## 聚合：为什么比率不能取 min/max

这一条是第一版**实测暴露出来的**，不是设计时想到的。

`crossValidationRate` 在黄金集上算出来 `min = 0`，闸门因此红了。
但那个 0 来自一份只有 3 条论点的报告（3 条都没被交叉验证）。
一份报告 3 条论点，这个比率只能取 0 / 0.33 / 0.67 / 1，
取"22 份里的最小值"等于在问"有没有哪一份碰巧是 0"——
**这是个噪声问题，不是质量问题。**

所以比率类走**合并**：`Σ分子 / Σ分母`。它回答的是"这批报告整体上有多大比例的
论点被交叉验证了"，那才是这个数的意思。`RATE_PAIRS` 声明了每个比率的
分子/分母键和是否需要反转（`unsupportedClaimRate` 是
`1 - verified/claims`，存下来的是"已验证"）。

`min/median/max` 仍然打印出来给人看（它们能暴露单条的异常），只是不参与判定。

`hallucinationRate` **故意不在 `RATE_PAIRS` 里**：它的分母是"模型输出过的引用
编号数"，而那不是一个能被存下来的标量（`phantomCitations` 是绝对条数，
不是分母）。硬凑一个分母去合并会比 min/max 更错。

### 计数类看极值，不看均值

| 类型 | 看哪边 | 为什么 |
|---|---|---|
| 「至少要到 X」 | **min** | 最差的那条有没有跌破 |
| 「至多花 Y」 | **max** | 最贵的那条有没有超支 |

均值会把"一条烂到底"摊薄成"整体还行"。回归往往只出现在**一条** query 上：
某次改动让"几乎没有公开信息"那一类覆盖率掉到 0.2，其余 21 条纹丝不动——
均值看不出来，中位数更是完全不动。

方向由 `LOWER_IS_BETTER` 这个集合决定，**不是每个阈值各写一遍**。
理由：方向搞反的闸门**永远是绿的**，而它看起来和正常闸门一模一样。

## 闸门 vs 基线：契约，不是快照

- **闸门**（[`eval/thresholds.yaml`](../eval/thresholds.yaml)）是硬契约，
  写的是"不管哪条 query 都不许破"的线。破了**退出码 1**。
- **基线**（[`eval/baseline.json`](../eval/baseline.json)）是漂移检测，
  比"和上次比有没有变差超过 15%"。抓的是**慢慢变坏**：每条都还在阈值内，
  但整体已经比上个月差了一截。**不阻断 CI，只报告。**

把快照写进闸门，等于把闸门变成"和上次一样吗"——那样它既抓不到慢慢变坏，
又会在一次合理改动后变成需要手动更新的噪音，然后被加上 `continue-for-now`。

### 阈值分两类，取值依据不同

**机制背书的（必须严格）**——这些数**在结构上**就该是 0：

| 指标 | 线 | 为什么是结构性的 |
|---|---|---|
| `hallucinationRate` | `max: 0.0` | coercer 会丢掉不存在的引用编号 |
| `phantomCitations` | `max: 0` | 同上，非 0 说明有一个不存在的编号混进了正文 |
| `unsupportedClaimRate` | `max: 0.0` | 铁律一：没挂证据的论点会被降级而不是留下 |

它们不是"我们跑得好"，是"这件事不可能发生"——一旦非 0，
说明那层机制坏了，不是模型今天状态不好。

**质量判断的（留余量）**——取值在"实测最低值"与"明显坏了"之间，
**不贴着实测最低值写**：

| 指标 | 线 | 依据 |
|---|---|---|
| `dimensionCoverage` | `min: 0.6` | 计划维度至少六成要有证据锚定，否则是空架子 |
| `dimensionsCovered` | `min: 3` | 少于三个维度不构成一份对比分析 |
| `evidences` | `min: 20` | 实测区间 50–216 |
| `independentDomains` | `min: 3` | 等于 `citations.MIN_INDEPENDENT_DOMAINS`，铁律二的下限 |
| `crossValidationRate` | `min: 0.05` | 实测最低 0.083 |
| `degradedRate` | `max: 0.5` | 超过一半证据是降级的，依据太薄 |
| `llmOptionalFailures` | `max: 3` | 可选调用成片失败说明某一段在系统性挂 |
| `llmCalls` | `max: 40` | quick 档实测 13 次左右；到 40 说明有循环在重复调用 |

贴着实测最低值写会让闸门在正常波动下变红，
**而它变红一次就会被调松一次，最后什么都不剩。**

每条阈值都带一个 `why`，破线时会被打印出来。
写它的原因是：**看到红叉的人应该是拿着报错信息去修，而不是回来读这个文件。**

> `llmCalls` 的上界只对 `--live` 有意义（mock 恒为 0）。
> 写在这里是为了让"某次改动让调用数翻了三倍"能在花掉一笔钱之前就被看见。

### 漂移比对的两个细节

- **计时项不参与**：`DRIFT_EXCLUDED = {"durationMs", "firstEvidenceMs"}`。
  回放模式下这两个数**连网络时间都不含**，量的是本地进程调度——
  拿它做漂移检测的后果是每次运行都亮一盏黄灯。常亮的警告等于没有警告，
  还会把真正该看的几条（独立信源数、已验证论点、幻觉率）淹在噪音里。
  真要量耗时变化，用 `--live` 或 `--from-db`。

  实测印证：同一份报告实录 `durationMs = 50859`，回放 `187`。
  这个差值不是"变快了 271 倍"，是两个不相干的数。

- **绝对值很小的指标改用绝对增量判**：`phantomCitations` 常是 0，
  按相对变化判的话 `0 → 1` 会被算成"变差无穷倍"，而它其实只是差了一条。

## LLM-as-judge

只由 `--judge` 触发，且**不能配 `--gate`**（`--judge` 要读真实产出，
mock 的产出是模板）。它们有采样噪声，**所以不参与闸门**。

### 引用忠实度（[`judges/faithfulness.py`](../eval/judges/faithfulness.py)）

**这是判官指标里最有价值的一个，因为它量的是别处量不到的东西。**

`hallucinationRate` 量的是"引用的编号存不存在"——编号不存在，
coercer 会把它丢掉，所以那个数天然接近 0。而它**永远发现不了
"编号存在但内容不支持"**。后者才是真正会骗到人的那种：报告里每个论点后面
都挂着上标 `[12]`，点开也确实有第 12 条证据，只是那条证据讲的是另一件事。
**铁律一在字面上成立，在实质上不成立。**

- 三档：`支持` = 1.0 / `部分支持` = 0.5 / `不支持` = 0.0，取均值。
- **判"部分支持"是刻意的。** 只给两档会逼裁判在"证据讲了这件事但数字对不上"
  和"证据讲的是另一件事"之间二选一，而这两件事的严重程度差很远。
  三档之后，"部分支持"的比例本身就是一个信号：它高说明**证据找得还行、
  但引用时被拉伸了**。
- **只抽 20 条，且只抽有引用的论点。** 判一次要一次 `core` 档调用，
  判全部论点的成本会超过跑一遍流水线。20 条是按"够看出比例"定的：
  **真值 5% 时，20 条里一条没抽到的概率约 36%**，所以这个数
  **只用来发现大问题，不用来断言小差别**。
- **固定种子**（`seed=20260901`）：换一次跑就换一批样本的话，两次的忠实度不可比，
  而这个数唯一的用处就是比来比去。
- 解析失败判**"部分支持"**而不是"不支持"：裁判没答上来不等于证据不支持论点，
  记成"不支持"会让忠实度因为格式问题而虚低——**而虚低的数会被当成
  "质量真的变差了"，于是去改一个根本没坏的地方。**

判官看到的证据正文截断到 1200 字，**截断必须写进 prompt**（"以下是节选"），
否则裁判会拿"证据里没写"去判一个其实写在后面的东西。

### 可用性 rubric（[`judges/rubric.py`](../eval/judges/rubric.py)）

5 个维度各 1–5 分：

| 维度 | 判的是什么 | 扣分的典型形态 |
|---|---|---|
| 结构完整性 | 该有的章节在不在、有没有结论 | 有矩阵没结论，读者自己总结 |
| 论证充分性 | 论点有没有被证据撑住 | 结论对但后面没有引用 |
| 可操作性 | 读完能不能做一个决定 | 全是描述，没有"所以呢" |
| 区分度 | 对比有没有真的分出高下 | 功能矩阵一片 4 分 |
| 诚实度 | 不确定与降级有没有说出来 | 证据稀薄却写成板上钉钉 |

不是"全面性 / 深度 / 准确性"这类听起来对但没法判的维度——
**每一条都必须能被裁判指着报告里的某处给出分数**，否则它量的就是
"这份报告读起来专不专业"，而那和长度、术语密度高度相关，
最后会变成一个奖励废话的指标。

**「诚实度」这一维是这个 rubric 里最有意的一格。** 多数报告评测的 rubric
到这里就结束了，而 xm3 的四条铁律里有一条就是"不确定要说出来"。
一份证据稀薄但把自己说得很确定的报告应当在这一维拿低分——
不然"诚实"就只是文档里的一句话，没人真的量它。

**裁判看不到指标。** 递给裁判的只有报告正文，不给它看 `metrics`。
给了它就会去抄"维度覆盖率 0.83"然后给论证充分性打 4 分——
那是把确定性指标换了个说法再说一遍，判官指标就白跑了。

## 评测不写真库

评测跑 22 次流水线，每次都落库。落进 `backend/data/xm3.db` 的话，
**一次评测就往"我的调研"里灌 22 份没人看过的报告**——
而那个库本来就已经被测试污染过（见 `修补文档.md` D4b）。

所以 [`run_eval.py`](../eval/run_eval.py) 在**任何 `Settings` 被构造之前**
把 `DB_PATH` 指到一个临时文件，跑完删掉。

顺带一个好处：临时库每次是空的，所以**评测结果不依赖"库里原来有什么"**，
换个机器跑出来的数一样。

另有一条独立性要求：每条 query 之前都
`reset_providers()` + `reset_runners()` + `reset_mock_state()`。
不重置的话，前一条采到的证据 id 会留在 mock 的证据池里，
后一条的模型就可能"引用"到一条它从没检索过的证据——
**指标会好看，而它好看的原因是上一条的残留。**

## CI 里的五个 job

> ⚠️ **这五个 job 目前一次都没有执行过。** 仓库还没有 `git init`，
> 所以下面写的全是**配置**，不是运行结果。
> 而且第一次在本机跑 CI 里那条 ruff 命令时，它是 5 条错误——
> 也就是说 CI 一旦真的跑起来，会**停在 backend job 的第一步**，
> 五条错误已修，并加了一条本机守卫（见
> [`问题记录.md`](../问题记录.md) 的问题 50）。
> **在有人真的推上去之前，这一节描述的是"打算怎么跑"，不是"跑过了"。**

[`.github/workflows/ci.yml`](../.github/workflows/ci.yml) 把它们分开跑，
因为**它们失败的含义不同**，混成一个 job 之后一个红叉说不清是哪一类问题。

| job | 内容 | 红了是什么意思 |
|---|---|---|
| `backend` | ruff + pytest（排除 live） | 代码或测试有问题 |
| `frontend` | tsc + oxlint + vitest + `npm run build` + Playwright 冒烟 | 前端类型/行为/构建坏了 |
| `eval` | `--gate`（mock） | **代码结构性退步**，与模型质量无关 |
| `eval-replay` | `--replay`（真实录制） | **真实模型的产出违反了契约**，或录制过期了 |
| `docs` | `check_docs_order` | 改了流水线顺序忘改 `ARCHITECTURE.md` |

`eval` 与 `eval-replay` 分开，是因为两个都零花费、都跑同一份 `run_pipeline`，
但 `--replay` 能抓出 mock 抓不到的：**模型这次把不存在的 `evidence_id`
引用了、把编造的专家 id 写进了队伍、正文长度掉到阈值以下。**

**CI 里没有任何一步会联网调 API**，三条保证：
1. `pytest` 默认排除 `-m live`；
2. cassette 缺录制**直接抛异常**，绝不静默联网；
3. `eval --gate` 用 mock，`eval --replay` 走真实适配器 + cassette 回放。

少了这三条，"CI 跑绿"就变成一句**需要花钱才能相信的话**。

`eval-replay` 里还有一条看着像仪式的护栏，其实不是：

```yaml
- name: 确认没有 .env（回放不该靠它）
  run: |
    if [ -f backend/.env ]; then
      echo "::error::CI 里不该存在 backend/.env"; exit 1
    fi
```

它在钉住"回放查表，不发请求"这件事。哪天有人把录制路径做成
"读不到就联网"，这里会先炸，**而不是等到某个账单日**。

## 已知缺口

诚实列在这里，免得读者以为上面这套是完备的。

1. **mock 闸门 22 条全绿 ≠ 覆盖了 22 种输入形态。** 见开头那张表下面。
   唯一的补偿是 `--replay` / `--live`，而后者只跑过 5 条。
2. **黄金集 22 条里录过 5 条，现在回放得出来 4 条。**
   其余 18 条只在 mock 下跑过——它们的"证据形态差异"实际上
   从未被真实模型吃过。**账（`MANIFEST.json` 说 5）和事实（`--replay` 过 4）
   差一条**，差的正是 `vague-coffee-market`（唯一走澄清路径的那条）。
   详见 [`问题记录.md`](../问题记录.md) 的问题 51。
3. **判官指标没有基线可比**。`baseline.json` 的 `judges` 字段仍然是空的，
   因为它来自 `--replay`，而判官只配 `--live` 跑。`--live --repeat 3 --judge`
   已经手工跑过一次（15 份 · $0.39025，值见 [`项目总结.md`](../项目总结.md)），
   但**没有任何东西会自动拿新结果去比它**——
   "引用忠实度比上次高了"这句话**依然没有依据**。
4. **跨平台未验证。** 本地的**确定性指标**连跑多遍逐项相同（下表的 13 行），
   但换到 ubuntu runner 会不会因为并发搜索的完成顺序影响证据编号、
   进而让某条引用解析不到，没有验过。若 `eval-replay` 第一次在 CI 上红，
   先看 `hallucinationRate` / `phantomCitations` 是不是唯一的破线项——
   那属于"评测在别的平台上不成立"，而不是"代码退步了"。

   > **"逐项相同"要限定在哪些项上。** 上面那句指的是**确定性指标**
   > （`claims` / `evidences` / `hallucinationRate` / `phantomCitations` /
   > `independentDomains` / `llmCalls` … 共 13 行）。
   > **`durationMs` 与 `firstEvidenceMs` 不在其中，它们每次都不同**——
   > 那两行量的是墙钟，跟确定性无关。把整个表都说成"逐项相同"，
   > 是把一个真结论说成了一个大得多的结论。
5. **`--repeat N` 只对判官指标有意义。** 确定性指标一次就是定论，
   重复跑只是多花时间。这一点在 `metrics.py` 的模块 docstring 里写了，
   但没有在 CLI 上阻止"`--repeat 3` 配 `--gate`"这种无意义的组合。
6. **没有成本-质量前沿图。** 计划里写了"三档模式的效率倍数 vs 成本 vs
   引用忠实度帕累托图"，目前只有表格。三档各自的实测数字也还没齐——
   `expert` 档只在 mock 下跑过。
